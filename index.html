2 · The words

What changed, and why

Three lines do all the work up here. The headline keeps the question you wanted and adds the words that make it a commercial broker’s question instead of anyone’s. The sub-line is the one that needed the most work.

On the site today
Do you want to grow your CRE business?
Run your deals on the platform trusted with over $60B in lease volume.
I’m ready to grow

“CRE” is trade shorthand that reads as jargon to some brokers and as nothing at all to an owner or a principal. The sub-line spends the most valuable sentence on the site on a volume figure rather than on what the software does — so a broker reaches the button still not knowing Leasync is a CRM.

Recommended
Want to grow your business as a commercial real estate broker?
The software built for you. Your deals, exclusives, co‑broke splits and what you’re owed — all in one system.
I’m ready to grow

The headline now names its reader, on its own line, in mint. The visitor sees their own job title in the biggest text on the page. The sub-line says who it is for, then four things only a broker cares about. One button. The features preview underneath does the job the second button used to do.

Decide this before it ships: the $60B line

“Trusted with over $60B in lease volume” is hardcoded text on the page, not a number the product measures. It is the biggest claim on the homepage and the easiest one for a broker to ask about on a sales call. The recommended copy drops it. If you want a figure up there, it needs a source we can show.

The trust line under the button uses only published, verifiable facts: free plan, $59 starting price, 30-day money back.

4 · Handoff

Notes for the build

Everything here is copy-pasteable from this page’s source. No images, no video file, no animation library, no dependencies.

How the thirteen acts are stacked

All thirteen occupy the same grid cell, so the stage is always as tall as the tallest act and nothing on the page jumps when they swap. No fixed heights, no measuring, works at any width:

.stage-box { display: grid; }
.act       { grid-area: 1 / 1; opacity: 0; visibility: hidden; }
.act.live  { opacity: 1; visibility: visible; }

visibility is in there on purpose — without it the hidden acts still catch clicks and screen readers.

The sequencer

Every act is an array of [delay, fn] pairs fed to one scheduler that returns the act’s total length, so the tab progress bar and the hand-off to the next act stay in sync automatically. Retime a beat and nothing else needs touching.

function run(steps) {
  let t = 0;
  steps.forEach(([d, fn]) => { t += d; timers.push(setTimeout(fn, t)); });
  return t;  // act duration, drives the tab bar
}

Porting to React: one useReducer for act + per-act state, the same arrays inside a useEffect, clearTimeout in the cleanup.

How the card crosses the board

The four columns are a plain CSS grid. The travelling card is one absolutely positioned element on top, and the only thing that animates is a single translate3d(). Its width comes from CSS; its travel step is measured once in JS (and on resize), because a % inside transform refers to the element’s own box, not the board’s:

/* CSS: width. Absolutely positioned children measure 100% against
   the padding box, so subtract the padding to match 1fr columns */
--col: calc((100% - 2*var(--pad) - 3*var(--gap)) / 4);
transform: translate3d(calc(var(--stage) * var(--step)), 0, 0);

// JS, in measure():
board.style.setProperty('--step', col.getBoundingClientRect().width + gap + 'px');

The numbers can’t contradict each other

Board counts and totals are never hardcoded per state — each column holds a base number and the travelling deal adds itself only to the column it is currently in. Act 3’s $48,200, the two $24,100 halves, the three installments and the received meter all derive from one commission constant. The agenda’s “chase the $6,025 installment” is the next payment from act 3’s schedule, and the LOI reminder for Dana Park comes out of act 5.

Accessibility

  • The stage is aria-hidden="true"; the caption underneath carries the same information as text.
  • prefers-reduced-motion: no timers start, the stage renders the dashboard in its finished state.
  • The thirteen labels are real <button>s with role="tab" and aria-selected, keyboard reachable, visible focus ring. A click pins that act.
  • The hero headline is the page’s <h1> on the real site (it is an <h2> here only so this spec keeps a single <h1>). The audience phrase is a display:block; white-space:nowrap <em> so it always sits on its own line; below 640px it is allowed to wrap.

Mobile & performance

  • Below 860px the two-column acts drop to one column and the marketplace grid to two; the board scrolls sideways inside its own container. The page body never scrolls horizontally.
  • An IntersectionObserver pauses the whole loop when the hero leaves the viewport and resumes the same act when it comes back — a pinned feature stays pinned.
  • Only transform, opacity, width and SVG stroke-dashoffset animate. Compositor-friendly; no layout thrash.

Colours — all existing brand tokens

Every value is already in brand/tokens.css. Pipeline column headers use a mint value ramp instead of the app’s yellow / orange / blue / green, because red and orange are retired and a ramp reads as progress. Status pills are mint (positive) or sage (pending) — never red.

#16211C hero ground #E7E2D5 bone #F6F1E6 card #1F6B54 green #7FC4A9 mint #CDD6C7 sage

Type is Inter Tight for headings and Inter for everything else, both already shipping on leasync.ai. No monospace anywhere — figures use font-variant-numeric: tabular-nums to line up. Addresses are deliberately mixed (Atlanta, Brooklyn, Manhattan) so the hero reads as a national product.
